# Code Review Center

## Purpose

The Code Review Center lets engineers upload migration code and ETL artifacts, run AI-assisted analysis and review, inspect comments, compare original and generated drafts, and approve or reject generated artifact versions.

Helix Migration generates draft migration code, notebook structures, validation plans, and reconciliation reports that must be reviewed and approved by humans before production use.

## Code Upload

MVP upload types:

- `.py`
- `.sql`

Future upload types:

- `.ipynb`
- DAG files
- Config files
- SAS scripts
- dbt models
- ETL export files

Upload should create artifact metadata, a version record, content hash, and audit log. Uploaded code must not be executed during review. PostgreSQL stores artifact metadata only. File contents should use local filesystem storage in MVP and MinIO/S3-compatible storage later.

## Code Analysis

The Code Analyzer Agent extracts:

- Inputs
- Outputs
- Dependencies
- Transformations
- Joins
- Filters
- Aggregations
- Source and target references
- Risks
- Complexity score

## AI Review

The Code Review Agent checks:

- Code quality
- Anti-patterns
- Formatting issues
- Security risks
- Hardcoded secrets
- Performance issues
- Maintainability risks
- Dependency concerns

## Conversion Suggestions

The Code Migration Agent may generate draft target code or modernization suggestions. Each suggestion must include assumptions, limitations, and required human review.

Supported use cases:

- Python `.py` script to Databricks notebook draft
- SQL job to optimized SQL / dbt-style model draft
- SAS logic to Databricks notebook draft
- Legacy ETL script to PySpark draft
- Existing Airflow DAG review

## Diff Viewer

The side-by-side diff viewer should show:

- Original artifact
- Generated draft
- Added, changed, and removed lines
- Review comments
- AI assumptions
- Approval actions

## Review Comments

Comments may be:

- AI-generated
- Human-authored
- Line-level
- File-level
- Severity-tagged

Severity values:

- Info
- Warning
- High
- Critical

## Approvals

Generated artifacts support:

- Approve
- Reject
- Request changes

Approval records should include approver, artifact version, decision, notes, timestamp, and linked review.

## Version History

Version history should show:

- Version number
- Source hash
- Generated hash
- Generated by agent
- LLM provider and model
- Change summary
- Approval status
- Created timestamp

## Export Generated Code

Users may export approved or draft generated artifacts. Export should clearly show approval status and draft status where applicable.
